# Stage 4 — End-to-end Sepolia demo

Runs the full **register → observe → infer → prove → verify** flow against a deployed
`TrustMeshVerifier`.

## Prerequisites

1. Stage 3 contracts deployed to Sepolia (see `docs/deployments.md`).
2. Deployer/agent account funded with Sepolia ETH.
3. Contract owner has allowlisted an `E2E_TARGET_ADDRESS` (or use the same deployer key
   as owner — the script will call `addToRegistry` automatically).

## Setup

```bash
cd packages/prover
uv sync --extra e2e
cp e2e/.env.example e2e/.env
# Edit e2e/.env with SEPOLIA_RPC_URL, DEPLOYER_PRIVATE_KEY, TRUSTMESH_VERIFIER_ADDRESS
```

## Run

```bash
uv run python e2e/run_agent_demo.py
uv run python e2e/run_agent_demo.py --stream --scenario happy
uv run python e2e/run_agent_demo.py --stream --scenario unsafe
```

Outputs:

- Console log of each pipeline step with transaction hashes
- `e2e/run_log.json` — timing + audit records for documentation

## Scenarios

1. **Happy path** — valid proof, safety constraints satisfied, `VerifiedDecision` emitted.
2. **Constraint violation** — concentration cap exceeded; `eth_call` reverts and an on-chain
   failed transaction is broadcast for Etherscan evidence.

## Note on proofs

Stage 2 is not yet implemented. Proofs are generated by `trustmesh_prover.prover.proof.generate_proof`,
which matches the Stage 3 `MockPlonkVerifier` binding until Halo2 export is wired in.
